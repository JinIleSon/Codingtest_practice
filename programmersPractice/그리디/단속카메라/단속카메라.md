## 문제 설명

고속도로를 이동하는 차량의 진입/진출 지점이 담긴 배열 `routes`가 주어진다.  
모든 차량이 이동 중 단속용 카메라를 한 번은 만나도록 하려면 카메라를 최소 몇 대 설치해야 하는지 반환한다.  
차량의 진입/진출 지점에 카메라가 설치되어 있어도 카메라를 만난 것으로 간주한다.

| routes | return |
|--------|--------|
| `[[-20,-15], [-14,-5], [-18,-13], [-5,-3]]` | 2 |

---

## 입출력

**입력**
- 차량 대수 : 1대 이상 10,000대 이하
- `routes[i][0]` : i번째 차량의 진입 지점
- `routes[i][1]` : i번째 차량의 진출 지점
- 진입/진출 지점 : -30,000 이상 30,000 이하

**출력**
- 모든 차량이 카메라를 한 번은 만나도록 하는 데 필요한 최소 카메라 수

---

## 헷갈렸던 부분

**1. 정렬 기준을 진입 지점으로 잡으면 안 되는 이유**

처음엔 "정렬 후 하나씩 넣어보기"라는 방향만 잡고 어떤 값 기준으로 정렬할지가 불명확했다.  
진입 지점 기준으로 정렬하면, 순서대로 차량을 마주칠 때마다 이 차량이 언제 나가는지 모르는 채로 카메라 위치를 판단해야 해서 기준점이 차량마다 제각각으로 튀게 된다.  
결국 필요 이상으로 카메라가 늘어나 최소 개수를 보장하지 못한다.

**2. 왜 진출 지점 기준이어야 하는가**

진출 지점 기준으로 정렬하면, 앞에서부터 순서대로 **가장 먼저 나가는(=가장 제약이 빡빡한) 차량**을 먼저 마주치게 된다.  
이 차량의 진출 지점에 카메라를 놓으면, 그 차량을 잡을 수 있는 가장 오른쪽 끝(낭비 없는 위치)이면서 동시에 그보다 진입 지점이 앞선 다른 차량들까지 자연스럽게 같이 걸리게 된다.

**3. 그룹 내 기준값을 고정해야 하는 이유**

처음 짠 코드에서는 안쪽 반복문에서 비교 기준값을 `routes[i][1]`로 두었는데, `i`가 그룹 안에서 계속 움직이다 보니 "카메라를 놓기로 한 위치" 자체가 뒤로 슬금슬금 밀려나는 문제가 있었다.  
그룹이 시작되는 시점의 진출 지점(`j`)을 고정해두고, 그 값 하나만 기준으로 그룹 전체를 판단해야 카메라 위치가 흔들리지 않는다.

## 풀이 접근

### 핵심 아이디어 — 정렬 + 그리디

진출 지점 기준으로 오름차순 정렬한 뒤, 앞에서부터 순서대로 그룹을 만들어간다.  
한 그룹이 시작될 때의 진출 지점을 카메라 설치 위치로 고정하고, 그 위치로 커버되는 차량들을 같은 그룹으로 묶는다.

```
그리디 선택 기준:
routes[j][1] (그룹 시작 차량의 진출 지점) >= routes[i+1][0] (다음 차량의 진입 지점)
   → 다음 차량도 같은 카메라로 커버됨, i += 1
그렇지 않으면
   → 새 그룹 시작, 카메라 한 대 추가
```

**Step 1.** `routes`를 진출 지점(`x[1]`) 기준 오름차순으로 정렬한다.

**Step 2.** `i = 0`에서 시작하고, 그룹이 시작될 때마다 `j = i`로 기준 위치를 고정한다.

**Step 3.** 다음 차량의 진입 지점이 `routes[j][1]`(고정된 카메라 위치) 이하이면 같은 그룹으로 묶고 `i += 1`.

**Step 4.** 더 이상 묶이지 않으면 카메라 한 대를 설치(`count += 1`)하고 다음 그룹으로 넘어간다(`i += 1`).

---

## 실패한 접근

```python
def solution(routes):
    count = 0
    length = len(routes)

    routes.sort(key=lambda x: (x[1], x[0]))

    i = 0
    while i < length:
        count += 1
        while i + 1 < length and routes[i][1] >= routes[i + 1][0] and routes[i][1] <= routes[i + 1][1]:
            i += 1
        count += 1
        i += 1

    return count
```

- **문제점 1** : 그룹 하나를 처리하는 동안 `count += 1`이 두 번 등장해서, 한 그룹당 카메라가 이중으로 세어졌다.
- **문제점 2** : 비교 기준값을 `routes[i][1]`로 두어서 `i`가 그룹 안에서 움직일 때마다 카메라 위치도 같이 밀려났다. 그룹 시작 시점의 값을 고정해두지 않으면 커버 범위 판단 자체가 흔들린다.

## 최종 코드

```python
def solution(routes):
    count = 0
    length = len(routes)

    routes.sort(key=lambda x: (x[1], x[0]))

    i = 0
    while i < length:
        j = i  # 그룹 시작 시점의 진출 지점(카메라 위치)을 고정
        while i + 1 < length and routes[j][1] >= routes[i + 1][0] and routes[j][1] <= routes[i + 1][1]:
            i += 1

        # 다음 차량이 고정된 카메라 위치로 커버되지 못해서 빠져나왔을 때
        count += 1
        i += 1

    return count
```

## 복잡도 분석

| 항목 | 복잡도 |
|------|--------|
| 시간 복잡도 | `O(n log n)` |
| 공간 복잡도 | `O(1)` |

> `n` = `routes`의 길이 (최대 10,000)

정렬에 `O(n log n)`, 이후 포인터 순회는 각 원소를 한 번씩만 보므로 `O(n)` → 전체 `O(n log n)`.  
추가로 쓰는 공간은 포인터 변수뿐이므로 `O(1)`.

## 배운 점

**정렬 기준이 그리디의 성패를 가른다**  
"정렬 후 순서대로 훑는다"는 뼈대만으로는 부족하고, 어떤 값을 기준으로 정렬하느냐가 로직이 성립하는지를 결정한다.  
진입 지점 정렬은 기준점을 제각각으로 만들지만, 진출 지점 정렬은 "가장 제약이 빡빡한 대상부터 처리한다"는 일관된 순서를 보장해준다.

**그룹의 기준값은 그룹이 시작될 때 고정한다**  
그룹을 순회하며 조건을 검사할 때, 비교 기준이 되는 값이 순회 중에 같이 움직이면 안 된다.  
"카메라를 이 위치에 놓기로 했다"는 결정을 그룹 시작 시점에 확정하고, 그룹이 끝날 때까지 그 값을 그대로 유지해야 한다.

**카운트 증가 위치는 한 곳으로 통일한다**  
반복문 안에서 같은 카운터를 여러 지점에서 증가시키면, 의도한 것보다 더 많이(혹은 적게) 세어지는 실수가 생기기 쉽다.  
"한 그룹 = 카메라 한 대"라는 규칙이 있다면, 그 증가 지점도 그룹당 정확히 한 번만 실행되도록 위치를 명확히 해야 한다.

---

> 이 문제의 핵심은 "진출 지점 기준 정렬 + 그룹 시작 시점의 위치 고정"이다.  
> 정렬 기준을 잘못 잡으면 최소 개수를 보장할 수 없고, 그룹 내 기준값을 고정하지 않으면 카메라 위치가 계속 밀려나는 실수로 이어진다.
