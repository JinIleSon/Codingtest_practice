## 문제 설명

사람들의 몸무게 배열 `people`과 구명보트의 무게 제한 `limit`가 주어진다.  
보트는 한 번에 최대 2명, 무게 합이 `limit` 이하일 때만 같이 탈 수 있다.  
모든 사람을 구출하는 데 필요한 최소 보트 수를 반환한다.

| people | limit | return |
|--------|-------|--------|
| `[70, 50, 80, 50]` | 100 | 3 |
| `[70, 80, 50]` | 100 | 3 |

---

## 입출력

**입력**
- `people` : 1명 이상 50,000명 이하, 각 몸무게는 40kg 이상 240kg 이하
- `limit` : 40kg 이상 240kg 이하 (항상 최대 몸무게보다 크게 주어짐)

**출력**
- 모든 사람을 구출하기 위해 필요한 최소 보트 수

---

## 헷갈렸던 부분

**1. 앞에서부터 짝짓는 것과 양끝에서 짝짓는 것의 차이**

처음엔 정렬 후 앞에서부터 순서대로 `[0] + [1]`, `[2] + [3]` 식으로 짝을 시도했다.  
이 경우 가벼운 사람끼리만 묶이고, 무거운 사람과 짝지을 기회를 잃어버린다.

예를 들어 `[10, 20, 30, 80]`, `limit = 100`일 때:
- 앞에서부터 짝짓기 → `(10+20)`, `30 혼자`, `80 혼자` → 보트 **3개**
- 양끝에서 짝짓기 → `(10+80)`, `(20+30)` → 보트 **2개**

**2. 가장 가벼운 사람을 누구와 짝지어야 하는가**

"가벼운 사람끼리 묶는 게 낭비 아닌가?" 라는 의문이 들었다.  
핵심은 **가장 무거운 사람이 누군가와 같이 탈 수 있다면, 가장 가벼운 사람이 그 기회를 써야 한다**는 점이다.  
더 무거운 사람이 그 자리를 차지하면 가벼운 사람은 결국 혼자 타는 보트가 늘어난다.

**3. 못 짝지어진 마지막 한 명 처리**

`i == j`인 경우, 즉 포인터가 같은 위치에 있을 때 아직 처리 안 된 사람 한 명이 남아있다.  
루프 조건이 `i < j`라서 자동으로 처리되지 않으므로 루프 이후 별도로 `count += 1`을 해야 한다.

---

## 풀이 접근

### 핵심 아이디어 — 투 포인터 + 그리디

정렬 후 양쪽 끝(`i` = 가장 가벼운, `j` = 가장 무거운)에서 시작해 짝을 시도한다.  
무거운 사람을 먼저 처리하되, 가장 가벼운 사람과 같이 탈 수 있으면 같이 태운다.

```
그리디 선택 기준:
people[i] + people[j] <= limit  →  둘 다 같이 탑승, i+=1, j-=1, count += 1
people[i] + people[j] > limit   →  무거운 사람(j)만 혼자 탑승, j-=1, count += 1
```

**Step 1.** `people`을 오름차순 정렬한다.

**Step 2.** `i = 0`, `j = len(people) - 1`로 양끝 포인터를 세팅한다.

**Step 3.** `i < j`인 동안 반복한다.
- `people[i] + people[j] <= limit` 이면 둘이 같이 탑승 → `i += 1`, `j -= 1`, `count += 1`
- 초과하면 `j`만 혼자 탑승 → `j-=1-`, `count += 1`

**Step 4.** 루프 종료 후 `i == j`이면 남은 한 명을 혼자 태운다 → `count += 1`

---

## 최종 코드

```python
def solution(people, limit):

    count = 0

    people.sort()

    i = 0
    j = len(people) - 1

    while i < j:
        # 가장 가벼운 사람 + 가장 무거운 사람이 같이 탈 수 있으면 같이 탑승
        if people[i] + people[j] <= limit:
            count += 1
            i += 1
            j -= 1
        # 안 되면 무거운 사람만 혼자 탑승
        else:
            count += 1
            j -= 1

    # 포인터가 겹치면 한 명 남은 것
    if i == j:
        count += 1

    return count
```

## 복잡도 분석

| 항목 | 복잡도 |
|------|--------|
| 시간 복잡도 | `O(n log n)` |
| 공간 복잡도 | `O(1)` |

> `n` = `people`의 길이 (최대 50,000)

정렬에 `O(n log n)`, 투 포인터 순회에 `O(n)` → 전체 `O(n log n)`.  
포인터 두 개만 쓰므로 추가 공간은 `O(1)`.

## 배운 점

**투 포인터 패턴**  
정렬된 배열에서 두 원소의 합 조건을 다룰 때 투 포인터를 떠올려야 한다.  
앞에서부터 순서대로 짝짓는 게 아니라, 양끝에서 좁혀오는 방식이 핵심이다.

**그리디 선택의 방향**  
"가장 무거운 사람이 누군가와 같이 탈 수 있다면, 가장 가벼운 사람과 짝지어야 한다."  
더 무거운 사람을 짝으로 쓰면 가벼운 사람이 결국 혼자 타게 되므로 손해다.  
가장 가벼운 사람이 짝지을 수 없다면, 그 누구도 무거운 사람의 짝이 될 수 없다 → 무거운 사람은 혼자.

**경계 처리는 루프 밖에서**  
`i < j` 조건으로 루프를 돌면 `i == j`인 마지막 한 명은 루프 안에서 처리되지 않는다.  
루프 종료 후 별도로 확인해줘야 하는 후처리 예외다.

---

> 이 문제의 핵심은 "가장 무거운 사람을 중심으로, 가장 가벼운 사람과 짝이 되는지 확인"하는 그리디다.  
> 앞에서부터 짝짓는 직관을 버리고, 양끝에서 좁혀오는 투 포인터로 전환하는 것이 풀이의 전부다.
